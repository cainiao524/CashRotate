# 0011 提醒（M3）

- 狀態：已採用（2026-11-01）
- 決策者：開發者，依 CLAUDE.md「提醒」規則實作

## 決定

- **分工**：
  - **Dart（core 的 `planReminders`）**：規劃從今天起 60 天內的提醒，並用使用者的語言寫好通知文字。
  - **Kotlin**：負責儲存、排程、顯示通知。所有文字都由 Dart 決定，Kotlin 端不含任何翻譯。
- **提醒種類**：
  - 扣款前：天數依每個項目的設定，可以多選當天、前 1、3、7、14、30 天。
  - 價格階段切換前的最後一期：加註「下次將從 X 變為 Y」。
  - 試用結束：用該項目的提醒天數。
  - 合約到期、保單 / 年費到期：前 30 天和前 7 天。
  - 浮動帳單：到期當天提醒確認金額。
  - 逾期域名：寬限期結束前 3 天和前 1 天。
  - 合租：每期扣款後 3 天，若還有人沒轉帳就提醒。
  - 暫停或已取消的項目不提醒；「待補」的項目也不提醒。
- **送出時間**：
  - 每天固定一個時間，預設 9:00，可在設定調整，以當地時區計算。
  - 同一項目、同一種提醒、同一天只送一則；同時符合多個天數時，留距離事件最近的那個。
  - id 為 `種類:項目:日期`，重新規劃時 id 不變，Kotlin 端可以直接取代或取消。
- **排程**：
  - 用 `AlarmManager.setAndAllowWhileIdle()`，屬於不精確的鬧鐘，系統省電（Doze）時仍可送達。同時最多排 64 個，其餘由每日補檢接上。
  - 不宣告 `USE_EXACT_ALARM` / `SCHEDULE_EXACT_ALARM`。
- **重新排程**：
  - `BOOT_COMPLETED`、`MY_PACKAGE_REPLACED`、`TIME_SET` 時重新排。
  - WorkManager 每日補檢（`androidx.work:work-runtime-ktx` 2.11.2，Apache-2.0）：重新排鬧鐘，並補發 24 小時內錯過的提醒。
- **通知上的按鈕**：
  - 「已付款」：Kotlin 先記下來，由 Dart 套用到資料庫。App 開著就立即套用，否則下次開啟時套用。
  - 「明天再提醒」：Kotlin 自行在 24 小時後再排一次。
  - 點通知會開啟該項目。
- **ReminderLog**：
  - Kotlin 記下預定時間、實際送達時間和使用者的動作，Dart 開啟 App 時抄進 ReminderLog。
  - 送達晚超過 1 小時算延遲。設定頁會顯示最近 30 天的延遲次數，並附電池設定引導。
- **權限**：
  - 第一次有提醒可排時，請求 `POST_NOTIFICATIONS`，每次安裝只問一次。
  - 之後可以從設定頁的「允許通知」再開。
- **廠牌引導**：依 `Build.MANUFACTURER` 顯示對應步驟，涵蓋小米 / Redmi / POCO、華為 / 榮耀、OPPO / realme / 一加、vivo / iQOO、三星，其他廠牌顯示通用步驟；另有「開啟電池設定」和「發送測試通知」。
- **新提醒已過時間**：例如下午才新增項目，而當天早上本來就有提醒，這則不補發。只有之前已排好、卻沒送到的提醒才補發。

## 限制

- **60 天的規劃範圍**：只要開啟 App 就會重新規劃。如果超過 60 天都沒開，之後的提醒就會停止；每日補檢無法在背景執行 Dart。
- **信用卡出帳與繳款提醒**：要等 M4 的「付款方式」才能做。
- **尚未實機測試**：還沒在實機或模擬器上測試各廠牌的實際送達情形。Kotlin 端也沒有單元測試，邏輯都在 Dart 端測試。
