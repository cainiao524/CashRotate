# 0006 M2：項目編輯、匯率、首次設定的設計決定

- 狀態：已採用（2026-10-29）

## 金額與幣別

- **顯示**：使用 intl 的 `NumberFormat.currency`，千分位和小數點依地區格式。有歧義的符號一律加前綴：NT$、US$、HK$、JP¥、CN¥、S$、A$ 等。沒有通用前綴的共用符號（Rs、K、F、сом 等）直接顯示 ISO 代碼，後面加不換行空格，例如「LKR 1,500.00」。顯示時用銀行家捨入，儲存的金額不會改動。
- **輸入**：`parseMoney` 接受 `.` 或 `,` 作為小數點。單一逗號後接三位數視為千分位（1,000）；單一點後接三位數則視為小數，而且位數太多會被拒絕（20.001），不會被當成兩萬。零小數位的幣別（JPY 等）兩種寫法都視為千分位。
- **符號判斷**：先比對無歧義的符號和詞（刀、日圓、蚊等），再依「預設庫的計價幣別 → 使用者地區」決定。都判斷不出來時回傳 null，由呼叫端詢問使用者。
- **匯率**：用 BigInt 有理數精確計算。找不到直接匯率時，可以經由一個中間幣別換算（例如 JPY → USD → TWD），日期取兩者中較舊的那個。海外交易手續費以基點計（150 = 1.5%）。免費版只有手動匯率，存在 `exchange_rates` 表並隨同步。同一組幣別只保留一個方向，避免兩個方向的匯率互相矛盾。

## 資料庫 v2

- 新增 `app_settings`（會同步的設定：主要幣別、地區、語言、首次設定進度）和 `exchange_rates` 兩張表。
- Items 新增 `needs_details` 欄位，用來標記「待補」。
- occurrences 改以到期日識別（見 ADR 0004）。
- 遷移由 drift 的 `SchemaVerifier` 測試：從真正的 v1 資料庫升級，驗證結果等於 v2 schema，而且舊資料會保留。

## 編輯器

- `ItemDraft` 是純邏輯的表單模型，可以單元測試。它負責驗證（勾選首期優惠時續費價必填、優惠價可以是 0 代表試用、期數至少 1），並轉換成 `NewItem`。
- 「下次扣款日」視為明確指示：存檔時把 paidUntil 設為這一天。編輯時如果新日期仍落在原本的排程上，就保留原本的錨定日，讓期數維持穩定。
- 各類型的專屬欄位依「項目類型 + 預設庫的 fields」顯示，存成 JSON。遊戲伺服器可以關聯到自己的伺服器項目，關聯後不計入每月總額，避免重複計算。
- 合租：總價、人數、我的份額（預設平均分攤）、每個人是否已轉帳。項目本身的扣款金額不變。

## 首次設定與批次表格

- 首次設定是一個路由（`/onboarding`），由 router 依 `onboarding_done` 自動導向。**不能放在 `MaterialApp.builder` 裡**：那裡沒有 Navigator 和 Overlay，對話框、日期選擇器和 tooltip 都會當掉。這個問題是寫測試時發現並修正的。
- 每次變更後，進度（目前步驟和每一列的內容）都存進 `app_settings.onboarding_draft`。中途離開再回來，會回到同一步、同樣的資料。
- 批次表格只問金額、扣款日、幣別。留空的列會存成金額 0、日期為今天，並標記 `needsDetails`，首頁會顯示「還有 N 項待補」。勾選多列後，可以一次套用同一個扣款日或幣別；鍵盤按「下一步」會跳到下一列的金額欄。
- 「貼上清單」和「從 WebDAV 還原」兩個入口先顯示為停用，分別在 M6、M5 提供。

## 每月固定支出總額

- 用每個項目下一期的實際價格（優惠期間就是優惠價）換算成每月平均成本，再換算成主要幣別。
- 排除定期轉出、暫停或取消的項目、待補的項目，以及架在自己 VPS 上的遊戲伺服器。沒有匯率的外幣項目不計入總額，畫面上會註明。

## 測試基礎

- `clockProvider` 統一提供「今天」；測試固定在 2026-03-15，golden 圖不會每天變。
- `testApp` 在測試結束前先卸載 App，再推進虛擬時間，讓 drift 延後執行的串流清理跑完。in-memory 資料庫不手動關閉，因為關閉會等待綁在 fake-async zone 的工作，造成卡死。
- 測試直接從檔案讀取預設庫並注入 App，不經過 `rootBundle`，因為它的快取跨測試會卡住。
- Golden 共 8 個畫面 × 30 種組合 = 240 張，只在 Linux 上比對像素。Windows 上一樣會跑，用來抓版面溢出這類錯誤。
