# 0004 資料格式、週期與價格階段引擎

- 狀態：已採用（2026-10-28）
- 依據：計畫 §3（已確認）、CLAUDE.md「資料模型」與「日期與價格」規則

## 儲存慣例

| 資料 | 格式 | 理由 |
| --- | --- | --- |
| ID | UUIDv7 文字 | 依時間排序，各裝置離線產生也不會衝突 |
| 可推導的列 | Occurrence：`<itemId>:<到期日 yyyy-MM-dd>`；價格階段：`<itemId>:<序號>` | 每台裝置算出的 ID 相同，同步時可以直接合併 |
| 金額 | 最小貨幣單位整數 + ISO 4217 代碼 | 不用浮點數 |
| 匯率 | 十進位字串 | 交易確認後就固定，不受日後匯率變動影響 |
| 日曆日（到期、錨定、paidUntil） | `yyyy-MM-dd` 文字 | **刻意不存 UTC**：使用者換時區或出國時，繳費日不會偏移一天 |
| 時間點（建立、交易、提醒） | UTC 毫秒整數 | 依當地時區顯示 |
| 列舉 | 存名稱 | 之後新增列舉值，舊資料不會錯位 |
| 類型專屬欄位、提醒規則、合租 | JSON 文字 | 欄位形狀在 M2、M3 定義，不必每次改資料表 |

## 同步日誌（ChangeLog）

每次寫入都在同一個交易內，依欄位寫一筆日誌：實體、列 ID、欄位、JSON 值、HLC。
- 新增：記錄所有欄位。更新：只記錄有變動的欄位。刪除：寫入一筆 `_deleted` 墓碑。
- HLC 是 `<12 位十六進位毫秒>-<4 位十六進位計數器>-<裝置 ID>`，用字串比較的順序就是時間先後。裝置 ID 是 UUIDv7，存在 `meta` 表。
- 對方時鐘超前 5 分鐘以上會被拒絕，避免一台時間錯誤的裝置把所有裝置的時鐘拉到未來。

## 週期引擎

- 週期單位為日、週、月、年，搭配「每 N 個單位」。預設選項有日、週、月、雙月、季、半年、年，其他都是自訂間隔。
- **每一期都從錨定日直接計算**（`錨定日 + k × 間隔`），不從上一期往後推，所以月底不會漂移：1/31 → 2/28 → 3/31 → 4/30。
- 每月 31 日這類不存在的日期，取當月最後一天；2/29 的年繳在平年落在 2/28。
- 換算月成本用公曆平均月長（146097 天 ÷ 4800 個月），四捨五入到最近的偶數（銀行家捨入），累計時不會一直偏向同一邊。
- 按小時計費的 VPS 不另設週期：服務商都是按月出帳，所以用月週期加估算金額，時薪記在類型專屬欄位。

## 價格階段

- 價格表是一串連續的階段。每個階段持續「N 期」、「到某日之前」或「無限期」，**只有最後一段可以是無限期**。所有階段使用同一種幣別，金額不能是負數，0 代表試用。
- 以下情況都用這同一個模型表示：首期優惠（續費價必填）、試用、電信綁約、域名首年價。
- **漲價**：`changedFrom(第 k 期, 新價格)` 保留第 k 期之前的階段，把正在進行的那一段截斷，再接上新的無限期價格，並寫入 PriceHistory。已付款和已跳過的 Occurrence 永遠不改。
- `changeAfter(k)` 讓提醒能顯示「下次將從 X 變為 Y」。

## Occurrence 展開

- 範圍：從第一筆未付款的期數，到今天加 12 個月。逾期未付的會保留，直到付款或跳過為止。
- **paidUntil**：服務已付到這一天（不含當天），下一期就在這天到期。一次付多年時，paidUntil 往後推 N 期，被涵蓋的待付期數會刪除。
- **暫停**：暫停日之後的待付期數會刪除。恢復後，暫停期間的帳單不會補產生。
- **取消**：取消日之後不再產生新的期數。在 paidUntil 之前，`isUsableOn` 仍回傳可用。
- 已付款和已跳過的 Occurrence 是歷史紀錄，重新規劃時不會碰到；已付款或已跳過的日期不會再規劃一次。
- **以到期日識別每一期**（M2 修訂）：同一項目同一天只會有一筆，唯一鍵是（項目, 到期日）。M1 原本用期數當 ID，但使用者在已有付款紀錄後更改扣款日時，新排程從第 0 期重新起算，會跟舊的已付第 0 期撞 ID，導致下一期扣款消失。期數現在只用來計算價格階段。schema v2 遷移時重建 occurrences 表。
- 每次寫入後都重新規劃，App 開啟時也會對所有項目重算一次（M3 會加上每日背景補檢）。
